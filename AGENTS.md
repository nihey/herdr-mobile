# Herdr Mobile

npm workspaces: `mobile/` is an Expo 57 / React Native / TypeScript Android app; `bridge/` is a Node.js 22 ESM GraphQL adapter for the installed Herdr Unix socket. This project needs no Strapi, database, worker, or external account service.

- All app data operations use Apollo Client 4 and explicit GraphQL schema/resolvers. No REST data endpoints or generic Herdr method passthrough.
- Use opaque Herdr workspace/tab/pane IDs. Never use an implicitly focused target for mutations.
- Native app credentials live in Expo SecureStore. Bridge token is generated locally in ignored `.local/`, mode 0600. Never commit or log credentials, terminal output, or prompts.
- Saved machines use a small v2 SecureStore index and separate immutable per-profile credential records. The index write commits a change; failed writes preserve the previous profile. Existing v1 pairing migrates on upgrade. Profiles deduplicate by normalized bridge origin (maximum 20).
- New sessions: the home **new** button opens a sheet (project or home folder → agent kind or terminal → optional first task or command). The bridge `startSession` opens a new unfocused tab in that workspace's project folder, waits read-only for the shell prompt, starts the agent and waits for Herdr readiness. The first task is a normal prompt sent afterwards; never resent, restored as the terminal draft (in memory) when uncertain. Tabs are never closed automatically.
- Any folder: the sheet's **browse folders…** (under **home folder**) lists a computer's folders through the authenticated `folders(path)` query: names only, never files, bounded (500 per level, 5 s), fetched fresh and never stored on the phone. `startSession`/`startTerminal` take `folder` instead of `workspaceId` (never both): the home folder → home workspace; a folder an open project's first pane is in → a new tab there (the `phone` workspace never counts); otherwise `workspace.create` with no label (Herdr names it after the folder), unfocused, its root pane used. The folder is resolved to its real path and checked before Herdr is contacted.
- Terminals: the same sheet's **terminal** chip opens a plain shell via `startTerminal` (new unfocused tab labelled `terminal`), in a project or (null workspace) the home workspace: the workspace labelled `phone`, found by label, created in the bridge user's home on first use. Agent sessions accept the home workspace too. The bridge never types into a new shell; the app sends an optional first command (text, then Enter) only when the shell is ready, never resent. Plain terminals' Run = text + Enter; Type = no Enter.
- Hermes coordinator: the home screen pins a Hermes chat (one per computer) that can list, read, message and start the computer's agents. The bridge runs `bridge/hermes/host.py` under Hermes's own virtualenv (`HERMES_SAFE_MODE=1`, tool search and session titles off in-process), with exactly four tools relayed over stdio to the bridge; it refuses to start Hermes if any other tool appears. Send guards are bridge-enforced: sends/starts only inside a user turn, at most 3 per user message, a stopped request never runs later, and chips come from the bridge's record. Model: Codex's `model` (`~/.codex/config.toml`) via Hermes's `openai-codex` provider at medium effort, falling back visibly to Hermes's default when Codex's model isn't available. The user's Hermes config is never written; `.local/hermes-state.json` (0600) holds only the session ID and verified model. Hermes's messages and what it reads go to its model provider (PRIVACY.md).
- Home screen widget (`react-native-android-widget`, configured in app.json; entry `mobile/index.ts` registers its task): the active machine's agents grouped ● input / ◐ working / ○ idle (done and unknown count as idle), read-only. It reads credentials with `MachineStore.peek()` (no migration, no writes) and fetches the explicit `WIDGET_AGENTS` query with a 15 s timeout. The last snapshot per machine lives in JS memory only (the library keeps just the last rendered widget image, in private storage; PRIVACY.md). The app's `SESSION` polls redraw it, and machine changes refresh it. Rows deep-link to `agent/<paneId>?machineId=…`; never send anything from the widget.
- Starting Herdr: when Herdr's socket is missing or refuses the bridge (`not_running`, e.g. after a crash), the home screen offers **start herdr** instead of the error. Any other connection failure (`unavailable`: a frozen Herdr's full queue, permissions) or a timeout is never offered a start, so a second Herdr is never started over a running one. `startHerdr` pings first, then runs exactly `herdr [--session <name>] server` for the session that owns the configured socket (a custom socket is refused), in its own transient systemd user unit (`systemd-run --user --collect`, unit `herdr-mobile-server[-<session>].service`, output discarded) so restarting the bridge never kills Herdr, or as a tracked detached child where there is no systemd, and waits up to 20 s for it to answer (about 35 s worst case, under the app's 45 s timeout). Herdr restores its own workspaces and resumes agents. One tap per start: no automatic starts or retries, never stop or restart.
- Tailscale discovery is an authenticated GraphQL query backed by a bounded local `tailscale status --json` call. Return only peer identity/name, tailnet addresses, OS and online/self flags. No remote probing or installation.
- Machine changes stop the previous Apollo client and reset host-specific UI. Agent routes require the active machine ID as well as the pane ID; never resolve a route from another host.
- Default network binding is the Tailscale IPv4, not 0.0.0.0. Local HTTP is for the encrypted tailnet. Use HTTPS if exposed through a TLS endpoint.
- The Android app ships as "Herd Remote" (`io.github.nihey.herdremote`), an unofficial Herdr companion. Never brand it as Herdr itself or imply affiliation. The package is permanent on Google Play. PRIVACY.md is the Play privacy policy; keep it accurate when data handling changes.
- Release builds are signed with a private upload key from ignored `.local/upload-keystore.properties`, passed to Gradle via the environment, never argv. Play bundles refuse to build without it; never commit, print or log the key or its passwords.
- Voice dictation is on-device only (Android offline speech models, English and pt-BR). Audio and transcripts never leave the phone; dictation fills the draft and never sends by itself.
- No automatic mutation retries. A failed connection after submission means uncertain delivery.
- Do not test by sending prompts or keys to existing user agents. Use a disposable named Herdr session or a mock socket.
- Native directories are generated by Expo prebuild. Change app.json/plugins, never generated Gradle/manifest files.
- UI uses React Native primitives, native Modal dialogs and lucide-react-native; web-only shadcn/Tailwind patterns do not apply to this Expo app.
- Run `npm run lint:fix`, `npm run typecheck`, `npm test`, and relevant builds before committing.
- Document architecture/features in this file and subproject AGENTS.md; update README for setup changes.
- Public source, fixtures, screenshots and commit metadata must use example hosts/paths and a GitHub noreply email. Before publication, scan the entire Git history for secrets and real machine details; keep scan reports and original-history backups in ignored local storage. See SECURITY.md.
