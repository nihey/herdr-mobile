# Bridge

- TypeScript strict mode, Node 22+, ESM (`.js` extensions in TS imports).
- `src/socket.ts`: bounded one-request-per-connection JSON socket transport, unique request IDs, no retries.
- `src/schema.ts`: explicit GraphQL schema, camelCase fields mapped from Herdr snake_case, validation before daemon access.
- `src/server.ts`: authentication before request parsing/execution, bounded body/query size, POST-only /graphql.
- `src/config.ts`: Tailscale IP discovery, socket/env configuration, credential generation. `src/index.ts`: HTTP listener and CLI pairing output.
- `src/discovery.ts`: bounded async `tailscale status --json` (4 seconds, 2 MiB), safe field projection, private tailnet IP validation, shared in-flight reads and a 10-second success cache. Discovery uses the connected bridge's visibility; it does not check remote bridge installation or phone reachability.
- Output reads: a RECENT read first checks `pane.get` scroll info. With no scrollback (`max_offset_from_bottom: 0`: a fresh shell or a full-screen app on the alternate screen, such as Claude's TUI) it reads `visible` instead. For alternate-screen panes Herdr would otherwise harvest history by sending mouse-wheel events to the app, which scrolls it on the user's desktop when idle, and it refuses (`agent_not_idle`) while working. An `agent_not_idle` refusal still falls back to `visible`, since it is a read.
- Installed `herdr api schema --json` is the source of truth. RECENT reads use Herdr's `recent` source: rows wrapped at the pane's width, exactly as the computer shows them (the app never re-wraps them). Use the API spellings (`recent_unwrapped`, not the CLI's `recent-unwrapped`).
- GraphQL maps session snapshot, agent/pane output, prompts, keys, literal terminal text, agent startup and plain terminals. Server shutdown is not exposed, and the bridge never runs commands itself: terminals are Herdr panes the user types into through `sendText`/`sendKeys`.
- `Workspace.cwd` is the shell cwd (fallback foreground cwd) of the workspace's first pane. `Query.agentKinds` lists validated kinds from `server.agent_manifests` (supported, not necessarily installed).
- `Mutation.startSession(workspaceId, kind, name)`: `tab.create` (`focus: false`, label = name, project cwd) → read-only `pane.process_info` polling until the shell is alone in the foreground (startup scripts finish) → `agent.start` → `agent.wait` for idle/done/blocked. Returns `ready: false` if still starting within the 38 s budget (under the app's 45 s timeout). agent.start succeeds before the launch is confirmed, so `agent.wait` → `agent_not_found` (e.g. CLI not installed) is a failed start. Duplicate live agent names are rejected before `tab.create`. The shell check and `agentKinds` are optional and never block a start. Start failures keep the daemon code and add `paneId`/`tabId` extensions; blocked at startup is `agent_not_ready`. No retries. Read-only methods are listed in `socket.ts` so their transport failures are not reported as uncertain delivery.
- `Mutation.startTerminal(workspaceId)` opens a plain shell: `tab.create` (`focus: false`, label `terminal`, project cwd) → the same read-only shell wait; `ready` is true only once the shell sat alone at its prompt (false on timeout or when process info is unavailable). It never types anything. `Query.homeFolder` is the bridge user's home (`createBridge({ homeDir })` in tests).
- A null `workspaceId` on `startTerminal`/`startSession` means the home workspace: the workspace labelled `phone`, found by label alone (workspaces have no folder of their own; a shell's cwd changes with every `cd`). If none exists, `workspace.create { label: 'phone', cwd: home, focus: false }` and its root pane is used instead of a new tab. A workspace the user names `phone` counts as the home workspace.
- `src/actions.ts`: Herdr actions shared by the resolvers and the Hermes tools (snapshot, full-screen-safe `readOutput`, `prompt`, `startSession`, `startTerminal`, validators). Resolvers are thin wrappers; error codes and messages are unchanged.
- Hermes (`src/hermes/`): `host.ts` spawns `<HERDR_MOBILE_HERMES_PYTHON, default ~/.hermes/hermes-agent/venv/bin/python> -I bridge/hermes/host.py` with every `HERDR_*` variable removed and stderr discarded (Hermes logs can quote the conversation); JSON lines per `protocol.ts`, 4 MiB line cap. `host.py` depends on Hermes internals (verified on 0.21.0 and on git `b200f5b`, 2026.9.24): it imports `hermes_bootstrap` first like every Hermes entry point (newer Hermes keeps its dependencies in a committed environment per data root that this activates; a fresh `HERMES_HOME` installs it first, which takes a minute or more), keeps a private dup of stdout for the protocol (passed on in `HERD_HOST_OUT_FD` if Hermes re-launches the process) and points fd 1 at `/dev/null` (Hermes swallows `sys.stdout` and newer versions print tool progress straight to fd 1), marks a turn busy until its closing note is written and only then emits `turn_end`, sets `HERMES_SAFE_MODE=1` (no plugins, shell hooks, webhooks or configured MCP servers), turns tool search and auto-titles off by patching `tools.tool_search.load_config*` and `agent.title_generator._auto_title_enabled` in-process, registers the bridge's tool specs in toolset `herd_remote`, and builds `AIAgent(enabled_toolsets=['herd_remote'], skip_context_files, skip_memory, reasoning medium, SessionDB in $HERMES_HOME/state.db)`. History is reloaded from SessionDB each turn. Any request that did not finish cleanly (stopped, failed, or cut off by a restart or crash) is closed with the assistant note `That request was stopped before it finished. Nothing more will be done for it.` (after the turn, and on resume/before each turn when the session does not end on a final answer), so Hermes never merges it into the next message. Pending tool calls always get the bridge's real answer, even after cancel. The probe uses an empty toolset (no tools). Reloaded history carries only the last 200 items and summarized tool results (ids, titles, flags; never full reads), so `ready` stays small; a missing import/attribute is `fatal incompatible`, provider resolution failure `fatal signed_out`.
- `tools.ts`: `list_agents`, `read_agent` (last 200 lines / 24 KiB), `send_to_agent` (`agent.prompt` once), `start_agent` (project by label or folder name, else home; `startSession` then the first task once, only when ready). Guards: sends/starts refused without a user turn and after `CHANGES_PER_TURN` (3) in one turn; Herdr errors become tool errors; `delivery_unknown` tells Hermes not to resend.
- `coordinator.ts`: lazy host start on first `hermes` query; exact tool-list check (else UNAVAILABLE and the host is stopped); model from `codexModel()` with `probe: true` until verified (state file), probe `modelMissing` → restart with Hermes's default and a visible `modelNote`; no Codex config → Hermes's own default. One turn at a time (`hermes_busy`), 10-minute turn timeout (cancel + stopped), late tool calls run with no turn (refused), chips from the tool record, reloaded history mapped to chips (only successful tool results), a trailing unanswered user message shows as stopped. Stop is enforced by the bridge: the turn is marked cancelled at once (later tool calls run with no turn and are refused; `start_agent` checks again before starting and before its first task), and if Hermes does not confirm within 5 s the turn ends and the host is restarted. The 10-minute timeout stops the same way with the note `Hermes took too long and was stopped.` A start that is not ready within 90 s is retired (UNAVAILABLE, retried after 30 s). Message handling errors (e.g. an unwritable state file) mark Hermes unavailable instead of crashing the bridge. Uncertain sends (`delivery_unknown`) and starts that failed after opening a tab are recorded as `uncertain` chips. `conversation({ start: false })` (the home summary) never starts Hermes and reports `off`. Host exit → UNAVAILABLE, restart after 30 s. `fake-model.ts` (test-only, excluded from the build) is a scripted OpenAI-compatible server.
- GraphQL: `hermes(start = true) { status (OFF|STARTING|READY|UNAVAILABLE) reason model modelNote working messages(last) { id role text stopped at chips { kind paneId title uncertain } } }`, `hermesSend(text)` (≤ 16 KiB, never retried), `hermesStop`, `hermesNew`. Without a coordinator, `hermes` is UNAVAILABLE ("Hermes is not set up on this bridge."). `index.ts` wires the coordinator with `COORDINATOR_INSTRUCTIONS` and names new agents `<kind>-<4 hex>`.
- `Query.discoveredMachines` requires the same bearer token as all other data. Do not expose raw Tailscale status, peer keys, users, public endpoint addresses or traffic data.
- `npm run dev` runs tsx watch; `npm run build` and `npm start` run compiled code. Run commands from the root with `-w bridge` to preserve cwd/config behavior.
- Tests use a mock Unix socket and Yoga fetch adapter. Use root `npm test` for the complete suite.
